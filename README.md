# Kalah

Настольная игра калах (манкала) на Java: правила, бот с минимаксом, консольный
и десктопный клиенты. Логика вынесена в чистое ядро без зависимостей, поэтому
одна и та же реализация правил работает и офлайн в десктопе, и - в планах - на сервере.

## Модули

| Модуль | Назначение | Зависит от |
|---|---|---|
| `kalah-core` | правила игры: доска, посев, захват, лишний ход, завершение партии | — |
| `kalah-bot` | минимакс с альфа-бетой, уровни сложности, стили игры | core |
| `kalah-api` | контракт для клиентов: `GameSession`, `GameView`, `MoveStep` | core, bot |
| `kalah-cli` | консольный клиент | core, bot, api |
| `kalah-desktop` | десктопный клиент на JavaFX с анимацией | core, bot, api |

**`kalah-core` не имеет ни одной внешней зависимости и не должен её получить.**
На этом держится переносимость: ядро подключается как обычный jar в офлайн-клиент,
на сервер и потенциально в Android.

## Правила

Доска - 12 лунок (по 6 на игрока) и 2 калаха. В начале в каждой лунке 4 камня.

- Игрок берёт все камни из своей лунки и раскладывает по одному по часовой стрелке,
  включая **свой** калах и пропуская **чужой**.
- Последний камень попал в свой калах - игрок ходит ещё раз.
- Последний камень попал в свою пустую лунку, а напротив у соперника есть камни -
  игрок забирает свой камень и все камни напротив.
- Когда сторона одного из игроков опустела, оставшиеся камни другого уходят в его калах.
  Побеждает тот, у кого в калахе больше.

Индексация: `0–5` - лунки SOUTH, `6` - его калах, `7–12` - лунки NORTH, `13` - его калах.

## Бот

Минимакс с альфа-бета отсечением и сортировкой ходов.

Особенность калаха: из-за лишних ходов стороны **не чередуются строго**, поэтому
роль узла определяется не чётностью глубины, а тем, кто реально ходит в позиции.

### Уровни сложности

| Уровень | Глубина | Допуск |
|---|---|---|
| `Easy` | 5 | 30 |
| `Medium` | 7 | 10 |
| `Hard` | 9 | 0 |

Допуск - насколько ход может отставать от лучшего, чтобы бот всё ещё мог его выбрать
(10 очков ~ 1 камень). На нулевом допуске бот играет строго оптимально,
на ненулевом ошибается контролируемо и не повторяет одну и ту же партию.

### Стили игры

`Personality` - линейная свёртка пяти признаков позиции: материал, камни на своей
стороне, возможный захват, риск быть захваченным, доступные лишние ходы.
Готовые наборы: `Greedy`, `Aggressive`, `Balanced`, `Defensive`.

## Производительность

Замеры на 100 позициях, глубина 8:

| Вариант | Узлов | Время |
|---|---|---|
| без отсечения | 2 217 706 | 412 мс |
| альфа-бета | ~220 000 | 41 мс |
| альфа-бета + сортировка ходов | 541 150 → 127 мс* | 127 мс |

Время на ход с сортировкой: глубина 9 - 2 мс, глубина 11 - 10 мс, глубина 13 - 51 мс.

сортировка сокращает дерево вчетверо относительно варианта без неё.

## Упаковка десктопа

```
powershell -ExecutionPolicy Bypass -File package-desktop.ps1
```

Скрипт собирает проект, вызывает `jpackage --type app-image` и пакует результат в zip.
Получается переносимая папка с `Kalah.exe` и вшитой JRE — установщик, права
администратора и установленная Java пользователю не нужны.

Образ собирается под ту ОС, на которой запущен скрипт.

## Архитектура

Клиенты не работают с движком напрямую, а ходят через `GameSession`:

```java
public interface GameSession {
    GameView view();
    GameView move(int pit);
}
```

Сейчас реализация одна - `LocalSession`, считающая партию в этом же процессе.
Когда появится сервер, добавится `RemoteSession`, и клиенты не изменятся.

`GameView` содержит доску, чей ход, список доступных лунок и `MoveStep` - шаги
перехода. Каждый шаг несёт путь посева (`sowPath`) и доску после хода, чтобы клиент
мог проиграть посев по камню, **не зная правил**: порядок обхода и пропуск чужого
калаха вычисляет ядро.
